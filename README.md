# HANA云音乐（hana-music163）

HANA 里的网易云音乐播放控制台。整页卡片与侧栏面板读同一份状态，声音由页面里的 HTML5 `<audio>` 直接播放。

## 形态

- **卡片「HANA云音乐」**（全站导航入口）：封面、进度、播放控制、播放队列、搜索、歌词、歌单、红心、扫码登录。
- **侧栏功能面板 / 同伴卡「正在播放」**：与整页共用一份状态；整页不在场时它自己出声（音频执行器选举，v0.11.18 起）。

## 架构（三层）

```
取源层  lib/api.js + lib/service.js  →  由宿主托管运行时拉起本机 api-enhanced（127.0.0.1:3300）
状态层  lib/player.js    →  队列 / 当前曲目 / 期望播放态 / 位置（后端持"真相"）
执行层  受 `backend` 控制的二选一：`audio` → 页面里的 `<audio>`；`mpv` → 后端自己驱动的 mpv 进程
```

后端持真相，前端只当执行器。换成 mpv 后端时，只是把执行器从"页面"挪到"后端自己拉的进程"，状态语义不用改。

## 依赖的外部服务

- **api-enhanced**（`NeteaseCloudMusicApiEnhanced/api-enhanced`，MIT）：本机 `http://127.0.0.1:3300`。取源 / 搜索 / 歌单 / 歌词 / 登录都经它。
  - 不在应用包内（16943 文件 / 约 133 MB，含 `.git` 与 pnpm 软链接），放在 `<HANA_HOME>\app-data\hana-music163\api-enhanced`。
  - **启动方式**：App 载入时 `lib/service.js` 调 `sdk.runtime.start({ runtime:"node", entry:"runtime/api-enhanced-boot.cjs", profile:"local-machine", network:"external", service:{ port:3300, readyMarker:"Server started successfully", id:"api-enhanced" } })`。宿主的托管运行时子进程 env 是一份白名单（不含 `NODE_OPTIONS`），所以不需要 v0.1 那套 `NODE_OPTIONS` 垫片。
  - **更新 api-enhanced**：在它的目录里 `git pull`，再重启 HANA（或调 `POST /service/restart`）。
  - **换一台机器部署**：应用包不含它，需要在目标机 `git clone https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced.git` 到 `<HANA_HOME>\app-data\hana-music163\api-enhanced` 并 `npm install`（或从本机整目录拷贝，注意保留符号链接，`robocopy /E /SL`）。
  - **登录 cookie 走 `Cookie` 请求头**，不要走 query（`MUSIC_U` 里有 `+` `/`，URL decode 会破坏）。
  - **803 扫码成功返回的 `cookie` 字段是整段 Set-Cookie 拼接**（含 `Max-Age` / `Expires` / `Path` 等属性与 `;;`），必须先清洗（见 `lib/api.js` 的 `sanitizeCookie`），否则 `account` 返回 null、登录态丢失。

## 托管服务一览

本应用自带**三个**托管外部服务，都由宿主的托管运行时拉起（`profile: "local-machine"`）：

| 服务 | 端口 | 入口 | 何时起 |
|---|---|---|---|
| 取源 api-enhanced | 3300 | `runtime/api-enhanced-boot.cjs` | 随 App 载入 |
| mpv 桥 | 3310 | `runtime/mpv-bridge.cjs` | 切到 MPV 后端时（懒启动） |
| 下载器 | 3320 | `runtime/downloader.cjs` | 第一次下载 / 打开本地库时（懒启动） |

**为什么这些活儿都放在子进程**：应用进程出站只放行 HTTPS、响应上限 8MB、文件系统写权限只覆盖自己的 `dataDir`；子进程（local-machine）这三条都不挡。所以字节下载、写用户目录、扫本地库、叫起资源管理器，全在子进程里做。

## 图标与卡面（v0.17.0 起）

两处图各自有规格，别混：

| 用途 | 声明在 | 文件 | 格式 | 比例 |
|---|---|---|---|---|
| App 图标 | `manifest.icon` | 包根相对路径（如 `assets/icon.png`） | PNG / JPEG / WebP / SVG | 正方形（非正方补透明留边，不裁） |
| 卡片卡面 | `contributes.cards[].face.image` | **相对 `ui/`**（如 `assets/cover.png` → `ui/assets/cover.png`） | **PNG / WebP / SVG**（JPEG 不行） | **2:3 竖版**（宿主居中裁切填满） |

- **图标尺寸没有硬要求**：宿主在新安装 / 更新 / 市场打包时生成展示版——位图长边超 256px 才等比缩到 256，
  非正方形补透明留白，小于 128px 只提示清晰度；SVG 走矢量不受低分辨率建议。预算是单文件 16 MiB、
  解码后 ≤6400 万像素。实用值：正方形 512×512 起，或直接给 SVG。
- **卡面 2:3 是渲染端定的**（两处印证：兜底卡面 SVG 的 `viewBox="0 0 640 960"`、卡面格 CSS 的
  `aspect-ratio: 2/3`），而且用 `slice` 居中裁切——给别的比例就会裁掉两边。
- `pageIcon`（整页卡在页面切换条里的小图标）与卡面同一套文法，但会**真解码一次**：
  带脚本 / 外链引用 / 动画（SMIL、CSS animation、APNG、动画 WebP）的图一律拒。
- 两张卡的名字：整页卡「**云音乐**」、同伴卡「**云音乐•Mini**」（`•` 是 U+2022 项目符号，不是中间点 `·`）。
- 本应用现状：图标 `assets/icon.webp`（512×512，WebP q0.95，90KB）、卡面 `ui/assets/cover.webp`
  （1024×1536 = 2:3，WebP q0.95，586KB，两张卡共用）；`pageIcon` 仍是 `ui/assets/nav.svg`。
- **选 WebP 的理由（v0.17.1 实测）**：这类水彩图的 PNG 体积虚高（纸纹属高频），换成 WebP q0.95 后
  图标 2213KB→90KB（同时降到 512²）、卡面 2909KB→586KB；逐像素比对：卡面高频能量保留 105%、
  平均色差 1.35/255、差>8 的通道仅 0.02%，纸纹没被吃掉。包体 7.36MB → 3.11MB。

## 下载与本地库（v0.11.46 ~ v0.11.50）

- **下载**：播放器栅一行「下载 [标准 128K / 320K MP3 / 无损 FLAC / Hi-Res FLAC] [整单下载]」；队列 / 搜索 / 歌单三种行尾都有一颗下载钮（悬停才显）。落盘规矩：先写 `.part`，核对 Content-Length 一致再改名；失败重试一次。文件名 `序号 歌手 - 歌名.ext`（整单带序号）。
- **整单下载一次最多 300 首，直链走批量接口（v0.16.5）**：`/song/url/v1?id=a,b,c…` 一次问回（100 首 ≈ 0.4 秒），
  不再一首一首问 —— 逐个问 100 首要十几秒，加上下单往返会超过宿主的等待上限，界面先弹
  「Internal Server Error」而后台还在继续下（v0.16.5 之前就是那样）。超过 300 首的部分会提示下次再排。
- **试听片段会标出来（v0.16.7）**：未登录时 VIP 曲目只给 20~60 秒（接口的 `freeTrialInfo` 直接写着 start/end，
  实测每日推荐 30 首里 24 首是这样）。队列行尾显示「试听 20s」，播放器下方那行写明
  「试听 N 秒（未登录只能听这一段，登录后听整曲）」—— 以前只会“放到一半停住”，看不出是试听还是出错。
- **未登录时只有标准档能选（v0.16.3，v0.16.6 扩到播放）**：匿名状态下网易云只给 128k，所以**播放的「音质」与下载的档位**
  两栏里除「标准」外的档都会**变灰**，当前值也收回标准，下方还有一行看得见的说明
  （`<option>` 的 title 在 Chromium 里不弹，所以不靠悬停）。**后端存的偏好不动** —— 登录后自然恢复。
- **后缀按接口实际给的格式定（v0.16.2）**：`ext` 取返回里的 `type`，不取请求的档位。
  原因：没登录时网易云接口会把**所有档都静默回落成 128k mp3**（实测九档 br/type 一模一样），
  照旧按请求档命名就会存出「`.flac` 里装 128k mp3」的**假无损**。发生回落时提示行会写明
  「实际只有 128kbps MP3（未登录时接口会回落，文件按实际格式存 .mp3）」。
- **默认下载目录**：`%USERPROFILE%\Downloads\HANA云音乐`（与机器无关）。本机可用 `POST /download/config {dir}` 改，会持久化到 `download-v1`。
- **下载音质档会记住（v0.5.1）**：那一档跟下载目录一起存在 `download-v1` 里；`GET /download/config` 会把它读回来，页面每次打开按存的那档回来（以前每次都跳回「无损」）。
- **打开目录**：点一下下载提示行，或 `POST /download/open`（由下载器子进程叫起 `explorer.exe`）。
- **本地库**：整页「本地」页签列出下载目录里的音频（只扫一层），点一行就把这批当队列起播。
  本地曲目**自带地址**（下载器的 `GET /file?p=…`，带 Range），播放时不去问网易云；音源核验与红心都会跳过它们。
- 路由：`GET /download/status`、`GET|POST /download/config`、`POST /download`、`POST /download/list`、`POST /download/open`、`GET /local/list`。
- **换一台机器部署**：应用包不含 api-enhanced（见上）；另外**下载目录会回到默认值**、**登录态要重新扫码**、
  **用 MPV 后端则目标机要有 mpv.exe**。这三件事 v0.16.0 起在整页的「环境」自检里都能看到（含两个依赖的引导安装）。

## 聊天框上方的歌词条（v0.12.0 ~ v0.18.1）

- **是什么**：一条挂在会话输入框**上方**的歌词带子。用的是宿主的 `app/input.panels`（App 自己的 ui 文档做面板内容），
  不是往宿主界面里注入。
- **挂在哪些会话（v0.17.3）**：以前只挂在「点开它的那个会话」上，切走歌词就没了；现在一次挂到**最近活跃的 5 个会话**
  （`lib/lyric-strip.js` 的 `RECENT_SESSIONS`，改这一个数就行）——口径跟 session-stats 那套一致：
  `sessions.list(scope=all, lifecycle=active)` 按 `modified` 倒序取前 5，再保证发起这次操作的那个会话一定在名单里。
  **收起是全局的**（一次把挂过的全摘掉），不是只摘当前那个。会话列表拿不到（权限未批 / 宿主报错）时退回「只挂当前这一个」。
  ⚠ 这是**开的那一刻的快照**，之后新开的会话不会自动补挂；要跟就得让它定期重列会话。
  ⚠ 5 个面板 = 5 个 iframe，各自每 2 秒轮询 `/state` 与 `/lyric-strip/config`。
- **四种显示方式**（名字是用户 2026-10-20 定的，四个都归到「水」的不同形态；id 仍是那四个英文键）：
  `center` **居盈**（2026-10-25 由“居庭”改名）—— 正在唱的那句居在中间并放大，
  **下一句在左、上一句在右**（两廊），与行云同向（2026-10-14 用户要求把左右对调过来的）；
  `shatter` **散雪** —— 唱完先胀一下，再碎成小雪粒被风吹散；
  `scroll` **行云** —— 字从左往右流，在**整宽减去左右各 `--ls-pad-x`** 的范围内活动，外圈不显示；
  `karaoke` **尽染**（2026-10-25 由“层染”改名）—— 逐字上色（墨一层层化开）。
  **循环顺序也是这个**（散雪 → 居盈 → 行云 → 尽染，2026-10-25 第二版重排），与 `STRIP_MODES` / `NEXT_MODE` 一致；
  钮上只有两字看不出功能，悬停时补一句老白话（中位固定 / 唱完散开 / 横向流动 / 逐字上色）。
- **居庭的换句交接（v0.18.2 ~ 0.18.5）**：
  主句字重**最终是 `600`（合成加粗）**。三条路都试过：400 太细 → 400+描边 0.35px「太干」→ **回 600**。
  结论：合成加粗虽会横向发胖、略糊，但**墨厚、不干**；描边只解决粗细，解决不了“润”。
  （所以别写 `font-synthesis: none`，它会把 600 降回 400。）
  换句时**不搬位置**：旧句交给一个与庭中同格叠放的「替身」（`#segGhost`）原地淡出（只往右挪 6px、
  缩到 0.92、糊到 1.4px，0.14s）；右廊接到的正好是**刚离开庭中的那句**，眼睛会连成「它走出去了」；
  新句 0.16s 后才起、**逐字落墨**（每字错峰 18ms、上浮 2px、封顶 200ms）。
  **方案 2：彻底不重叠** —— 庭心永远只有一句字，代价是中间有一瞬空窗。
  ⚠ 长句装不下 44vw 时**不拆字**（一拆 `text-overflow: ellipsis` 就废了），退回整句淡入。
  ⚠ 横向交棒（旧句真的走向右廊）用胶片验过：两句得同时穿过庭心，在 1000×40 里直接叠在一起，已放弃。

## 环境自检与引导安装（v0.16.0）

包里带不了两个外部依赖，所以应用自己会查、也会带你补：

- **取源服务 api-enhanced**（必需）：约 130MB / 1.7 万个文件，缺了搜不到任何歌；
- **mpv.exe**（可选）：只有「MPV 高保真」后端需要它，缺了不影响「界面播放」。

**入口**：整页顶部在环境未就绪时会显出一条引导带；标签行右侧那颗「环境」钮随时可开。
面板里是一张清单（每项 ✓/✗ + 一句人话），缺哪项就给哪项的按钮：

- 取源服务缺失 → **从本机拷**（填另一台机器上 api-enhanced 的目录，走 `robocopy /E /SL`，
  软链接按链接拷、不展开成实体）或 **在线装**（`git clone` + `npm install`，要这台机器有 git+npm，
  自检里会先告诉你有没有）；
- mpv 缺失 → 填一个 mpv.exe 的路径「记下它」（写进 `mpv.json` 的 `exePath`；桥会在自己进程启动时读它，
  所以路由会顺手把桥重起一次）。

**Agent 也能驱动**：`ncm_music action=setup` 读清单；`action=setup install=copy src=<目录>` /
`install=git` / `mpvPath=<路径>` 直接动手 —— 新机器上装完应用，一句话就能把环境弄好。

**路由**：`GET /setup/status`（清单）、`GET /setup/progress`（安装进度与日志）、
`POST /setup/api-enhanced {mode, srcDir?}`、`POST /setup/mpv {path}`、`POST /setup/cancel`。

**端点为什么挂在下载器上**：`runtime/setup-helper.cjs` 是逻辑本体，由 `runtime/downloader.cjs` 挂到 `/setup/*`
下转发（省一个常驻进程，且下载器本来就干本机的活）。⚠ 应用进程里**必须用 `sdk.network.fetch`**，
裸 `fetch()` 在 Node 权限模型下一律 `ERR_ACCESS_DENIED`（踩过，详见交接 §57）。

**自检顺手做的两件事**：① 取源服务已铺好却没在跑，就把它拉起来；② 装完/失败都会清掉检测缓存，
免得“刚装完再点一次自检还是那句缺”。

## mpv 高保真后端

页面够不到 mpv 的命名管道，所以中间加一座桥：`App/页面 --HTTP--> 桥(3310) --JSON IPC(命名管道)--> mpv.exe`。

- **默认关**，切到「MPV 高保真」才拉起来（懒启动）；配置在 `<HANA_HOME>\app-data\hana-music163\mpv.json`。
- 面板上多出一行「MPV 设备」：设备下拉（`GET /mpv/devices` 现拉）+ 「独占」勾选，改完写回 `mpv.json` 并让 mpv 下首重起。
- **独占按设备可用性自动开关（v0.8）**：虚拟音频设备（FxSound / Voicemeeter / VB-Audio 这类，
  以名字为种子，加上「哪台设备独占失败过就记进 `mpv.json` 的 `noExclusive`」的自我学习）
  会被标 `noExclusive: true`；选到这类设备时那个勾会**变灰、取消勾选**，并在下方写出原因与出路，
  而且**桥端会真的拒绝**这个组合（不会只是灰着）。
- 路由：`GET /mpv`（桥 + mpv 实况 + 配置）、`GET /mpv/devices`、`POST /mpv/config`、`POST /mpv/volume`、`POST /mpv/restart`。
- **音量归桥所有**（v0.5.3 起）：mpv 模式下页面那个音量滑块直接驱动桥（`POST /mpv/volume`），并在未被拖过时用实际值回填；桥端 `/volume` 会把设置写回 `mpv.json`，起 mpv 时用 `config.volume` 而不是「上次观察到的音量」。注意：`<audio>` 后端的音量是页面自己管的（`audio.volume`），两条路径互不相干。
- **实测（2026-10-03）**：花再 Halo Soundbar / S-PDIF / AMD HDMI 三个真硬件设备上 WASAPI 独占都能跑；**系统默认输出 `FxSound Audio Enhancer` 是虚拟 DSP，独占在它上面会「初始化成功、却持续喂不上数据」**（`AUDCLNT_E_RESOURCES_INVALIDATED` 刷屏、位置在走、耳朵里没声）。
- **音频输出自愈（v0.4.1 起，v0.5.1 ~ v0.5.2 补齐）**，五条：
  1. **预检**：播放前枚举设备，配置里那台不在了（拔掉/改名）就先摘掉、回退到系统默认；
  2. **级联**：真开不起来（`audio output initialization failed`）时依次退到 系统默认 → 关独占共享播放；
  3. **播放中监测**：独占若持续报 `AUDCLNT_E_*`（虚拟声卡的典型症状），6 秒内攒到 5 条就自动关独占、重载并续上原位；每次播放最多救一次。
  4. **失败事件触发**（v0.5.1）：输出设备**中途消失**时 mpv 会立即 idle，第 3 条那种「播放中才查」的巡检刚好错过，所以改成由 `end-file` 的失败事件直接触发恢复：先用 `resumePos` 记住的真进度当恢复点，再重走预检+级联。同一条 URL 最多救 2 次、间隔≥8 秒。当日实测：断电→恢复成功花 1.1 秒。
  5. **设备自报失效**（v0.5.2）：`AUDCLNT_E_DEVICE_INVALIDATED` 往往只吐一两条就静默下去，攒不够数，但**只在「用户显式指定了设备」时**才当成故障（自动模式下这条可能只是 mpv 跟着新默认设备重开），命中就直接改走系统默认。诊断口实测：注入→恢复成功 1.04 秒。
  回退会记在 `GET /status` 的 `fallback` 里（`fromDevice` / `toDevice` / `droppedExclusive` / `reason`），并随 `/state` 透出到页面与侧栏面板。
- `/status` 里 `config` 是用户选的、`effective` 是 mpv 实际在用的；两者可能不同（回退过）。mpv 空闲时 `position`/`duration` 一律报 0，免得把上一首的进度挂到当前曲目上。
- **设备消失感知（v0.5）**：播放中每秒看一眼设备表（异步枚举 + 8s 缓存，不阻塞 `/status`），用户指定的那台被拔掉就自动回退到系统默认并续上原位。

## 播放模式与队列

- **默认后端是「界面播放」**（用户的偏好）。它随**系统默认输出**走，界面上常驻一行提示说明这点；
  想 bit-perfect、或想绕开「系统默认被虚拟设备接管」的问题，手动切到 **MPV**（它直接点名设备）。
- **循环模式**：`off`（顺序）/ `all`（列表循环）/ `one`（单曲循环），主界面 ctrl 区右侧一个按钮循环切换；**随机**单独一个开关（开启时「下一首」与自动播完都会随机跳）。两者都持久化（`player-v2`）。后端动作：`control {action:"cycle-repeat"}` / `{action:"repeat",mode}` / `{action:"shuffle"}`。
- **队列行红心**：队列 / 搜索 / 歌单曲目每行都有红心，点一下即增删收藏（`POST /like/id {id,on}`；批量查已收藏用 `GET /liked?ids=1,2,3`，底接 api-enhanced 的 `/song/like/check`，注意它要求 ids 是 JSON 数组字符串）。
- **队列拖拽排序**：拖住队列行上下拖动即可重排（`control {action:"move",from,to}`，1 基）；重排会跟住当前正在播的那首。
- **mpv 的自动播完**用 `mpvLoadedId` 当「这次 eof 属于我们加载的那首」的凭据。mpv 空闲时 `eof` 会一直为真，不加这道闸的话每次 `/state` 轮询都会再推进一次、把队列连跳。

## 执行器在不在

`<audio>` 是「页面里的执行器」：整页关掉就没声。整页每 2.5s 打一次 `POST /progress {beat:true}` 当心跳，后端据此给出 `executorAlive`（6 秒窗口；mpv 后端恒为真）。侧栏面板在 audio 后端下如果 `wantPlaying` 但 `executorAlive` 为假，会直接写「整页未打开，声音不会出」。
- 独占对声源格式敏感：单声道测试音会 `AUDCLNT_E_UNSUPPORTED_FORMAT`，立体声（真实音乐）正常。
- mpv 暂停时**保持独占设备不放**，所以恢复很快；但期间其它程序出不了声，按「停止」才会真卸载音源、放开设备。
- 以 mpv 为后端时页面不再出声、也不再回报进度：真相全部由后端从桥取（`executor: "mpv"`）。

## 权限

- `capabilities`：`app/tools.expose-to-model` + `app/runtime.execute` / `app/runtime.local-machine` / `app/runtime.network`（后三个是托管拉起取源服务与 mpv 桥用的；扩能力后 reload 会弹一次用户确认，同能力重载不弹）。
- `network.allowedHosts`：`127.0.0.1`（本机取源）+ `*.music.126.net` / `*.126.net`（封面）。
- `allowLocalhost: true`，方法 GET / POST。

> Windows 上 `profile:"scoped"` 拿不到读/网隔离（宿主直接拒绝），`native` 需要管理员初始化过 helper，所以取源服务走 `local-machine`（用户已批准的本地应用档，无文件系统隔离）。

## 关键行为

- `<audio>` 只能走 Chromium/Electron 的 shared 输出模式；要 bit-perfect（WASAPI 独占）就切 MPV 后端。
- **reload 应用会卸载已打开的插件页**，页面代码随之中止，必须重新导航挂载，否则看到的只是上一份渲染结果。
- **reload 应用还会把它自己的两个托管服务（取源 + mpv 桥）一并重启**（v0.5.3 实测），所以它会把当前正在放的那首切断；动 reload 前先问用户。
- 桥重启后 App 会自己发现并重载当前曲目（比对桥端 `url`），但**位置从 0 重来**。
- **切后端时的设备归属（v0.5.4）**：从 MPV 切回「界面播放」时，mpv 只**暂停**不停止，把 WASAPI/蓝牙链路留住，
  交给页面的 `<audio>`；在界面播放模式按「停止」则真停 mpv、把设备放开。
- **界面播放不认「MPV 设备」那个选择**：页面的 `<audio>` 出到 Windows 的**默认输出**，App 看不见也改不了。
  界面上在「界面播放」模式会常驻一行提示说明这点；切过去时也会弹一句提醒。
  想让两个模式出口一致，理论上是 `HTMLMediaElement.setSinkId()`，但实测 HANA 渲染器只给一个**无名的默认输出**
  （`enumerateDevices` 的 audiooutput 只有 1 条且 label 为空，`speaker-selection` 权限不支持），
  宿主 SDK 也没有相关能力——所以这条路暂时封着，切换时若没声，去 Windows 里重选一次输出设备。
- **虚拟音频设备会抢默认**：本机装了 FxSound Audio Enhancer（一个虚拟 DSP，输出目标已指向花再），
  它会把自己设成默认设备。若它那一段没把声音转出去，界面播放就会没声——而 MPV 模式绕开了它。
  实测：退出 FxSound 后界面播放切回来即有声。
- **取源服务就绪前的请求会落空**：App 启动时不 await 服务，所以重载后头一两秒读账号/读歌单可能失败。已做三层兜底：服务就绪后补读账号、歌单路由自己补拿 userId、页面把失败不当成"读过"。
- 队列会持久化（`player-v2`），reload 后恢复上一份队列。

robocopy "…\OH-Works\Apps\hana-music163" "<HANA_HOME>\apps\hana-music163" /E /NFL /NDL /NJH /NJS /NC /NS /NP
